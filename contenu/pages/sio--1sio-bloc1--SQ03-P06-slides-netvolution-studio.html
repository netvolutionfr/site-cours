CMS : un logiciel pour gérer le contenu d’un site

CMS (Content Management System, système de gestion de contenu) : logiciel qui permet de créer et modifier les pages d’un site sans écrire le code ; il génère le HTML.

  • Contenu séparé de la présentation : on change la charte une fois, toutes les pages suivent.
  • Composants réutilisables : titre, bouton, galerie, carte, menu.
  • Page builder : on compose à la souris, en voyant le résultat (WYSIWYG).
  • Le référentiel B1.3 demande d’« étudier le CMS ou l’architecture utilisé » d’un site existant.

Netvolution Studio : un éditeur visuel qui produit un site statique

  • Projet libre (licence Apache 2.0), interface en français, dépôt public sur GitHub.
  • On compose : pages, menus, header/footer, design system, médiathèque, SEO.
  • Aperçu tablette et mobile, annuler/rétablir.
  • Le site est stocké en JSON ; l’export produit un projet Astro puis un site statique.
  • Une fois exporté, le site ne dépend plus du Studio.

L’éditeur : pages, canvas, inspecteur

Du poste au site en ligne

Installer un outil depuis son dépôt

node -v          # Node.js 24 ou plus
git clone https://github.com/netvolutionfr/netvolution-studio.git
cd netvolution-studio
npm ci           # installe les dépendances → node_modules/
npm run dev      # lance le Studio → http://127.0.0.1:5173/

git clone récupère le code source ; npm ci les bibliothèques exactes du package-lock.json ; npm run dev démarre un serveur local. Le terminal reste ouvert.

127.0.0.1 : volontairement inaccessible depuis le réseau

Le Studio n’a aucune authentification : quiconque atteint son port a tous les droits sur les projets (modifier, supprimer).

  • Il n’écoute que sur 127.0.0.1, la boucle locale : le poste lui-même.
  • Votre voisin ne peut pas ouvrir votre Studio, et c’est voulu.
  • Sur un serveur, on le place derrière un reverse proxy HTTPS avec mot de passe.
  • Le site exporté, lui, ne contient ni Studio, ni base de données, ni page d’administration.

À vous : installer puis créer un premier projet

30 min environ · binôme · un poste

Fiche TP, étapes 1 et 2 : installer, lancer, puis suivre le tutoriel du Studio (bouton ?) avec le modèle Atelier Nord.

À produire : le Studio lancé, une page « Tarifs » ajoutée au menu, et les réponses « À noter » 1 à 4 dans vos notes.

Un blocage ? Lire la dernière ligne du terminal avant d’appeler.

Ce qu’on retient avant le mini-projet

  • Le Studio est l’atelier : il tourne sur le poste, en local, sans authentification.
  • Le projet est un fichier JSON ; le HTML n’apparaît qu’à l’export.
  • Le site exporté : des fichiers statiques, servis par n’importe quel serveur web.

En demi-groupe : le site d’un client en trois pages, contrôlé et exporté. Plus tard (SQ04) : le déposer sur un vrai serveur Apache.
