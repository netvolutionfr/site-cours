  • Appuyer un diagnostic et une remédiation sur des éléments fournis.
  • Rédiger une réponse courte et précise, dans l’esprit de l’épreuve E7.

  • Aucun ordinateur, compte ou accès à une VM n’est nécessaire.

1. Situation

Le laboratoire de formation héberge la zone lab.test. Son serveur DNS dns.lab.test porte l’adresse 10.77.1.10. Les postes autorisés sont dans le réseau 10.77.1.0/24. Le serveur est censé faire autorité pour lab.test : il répond aux questions sur cette zone, sans chercher les réponses pour d’autres domaines. Aucun transfert complet de zone n’est prévu.

Une administratrice constate que la machine 10.77.2.50, située sur un autre réseau de test non autorisé mais pouvant joindre 10.77.1.10, a interrogé le serveur. Elle demande une analyse fondée sur les documents ci-dessous, sans supposer d’autres faits.

Repère. Un serveur faisant autorité publie les réponses de sa propre zone. Un résolveur récursif cherche des réponses pour ses clients auprès d’autres serveurs. Un transfert de zone (AXFR) fournit l’ensemble des enregistrements d’une zone.

Document A — Extrait de configuration en place

options {
    listen-on { 10.77.1.10; };
    allow-query { any; };
    allow-recursion { any; };
    recursion yes;
    allow-transfer { any; };
};

Document B — Résultats observés

Heure Source Demande Résultat
09:10 10.77.1.20 web.lab.test A 10.77.1.30, réponse faisant autorité
09:13 10.77.2.50 nom extérieur à lab.test réponse obtenue par récursion
09:14 10.77.2.50 transfert AXFR lab.test transfert accepté ; zone transmise

2. Questions d’analyse

1. Constater. Quelle ligne du document B montre un service normal pour les postes autorisés ? Citer la source, la demande et le résultat utile. Cette réponse est indépendante des questions suivantes.

2. Qualifier. Pour les lignes de 09:13 et 09:14, associer chaque résultat aux directives qui l’ont permis dans le document A. Expliquer en une phrase pourquoi chacun ne correspond pas au rôle prévu du serveur.

3. Mesurer le risque. Citer une information ou une capacité donnée à la machine non autorisée par chaque défaut. Ne pas prétendre qu’une attaque ultérieure a eu lieu : les documents ne le montrent pas.

4. Remédier. Proposer trois protections précises. Pour chacune, indiquer un test depuis le client adapté et le résultat attendu. Conserver la possibilité pour 10.77.1.20 d’obtenir web.lab.test.

3. Restitution : note d’incident

Rédiger 5 à 7 lignes pour l’administratrice : constat vérifiable, risque, mesures recommandées et tests après changement. Une phrase qui distingue « le nom se résout » de « le service web fonctionne » terminera la note.

Critère de réussite. Votre note relie chaque recommandation à un fait de la document B et annonce un test qui permet de vérifier la correction.
