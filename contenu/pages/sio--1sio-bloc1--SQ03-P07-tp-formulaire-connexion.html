Objectifs

  • Afficher un mot de passe masqué avec l’inspecteur, puis avec JavaScript.
  • Observer où part le mot de passe avec GET, puis avec POST.
  • Expliquer pourquoi les contrôles du navigateur ne protègent rien.

Prérequis

  • Balises HTML et attributs, inspecteur du navigateur.
  • querySelector et addEventListener (activité DOM).

Étape 1 — Lire et inspecter

À produire : une phrase qui dit ce que type="password" protège, et ce qu’il ne protège pas.

Étape 3 — Le bouton « Afficher »

20 minutes. Le bouton bouton-oeil existe déjà dans la page, mais il ne fait rien. Dans script.js, recopiez ce code et remplacez les ... :

const champ = document.querySelector("...");
const bouton = document.querySelector("...");

bouton.addEventListener("click", () => {
  if (champ.type === "password") {
    champ.type = "...";
    bouton.textContent = "...";
  } else {
    champ.type = "...";
    bouton.textContent = "...";
  }
});

Le if teste le type actuel du champ : s’il est masqué, on l’affiche, sinon on le masque. Le texte du bouton doit toujours annoncer ce que fera le prochain clic.

À produire : un bouton qui affiche puis masque le mot de passe à chaque clic, avec le bon texte.

Étape 4 — Défi : ce que voit un script

10 minutes.

  1. Saisissez un mot de passe fictif, laissez-le masqué. Ouvrez la Console des outils de développement et tapez : document.querySelector("#mot-de-passe").value. Qu’obtenez-vous ?
  2. Un site charge un script de statistiques hébergé chez une autre entreprise. Que pourrait faire ce script ?
  3. Le champ exige 12 caractères (minlength="12"). Dans l’inspecteur, supprimez cet attribut et envoyez un mot de passe de 3 caractères. Qui doit vérifier la longueur, finalement ?

À produire : deux phrases : ce qu’un script peut lire, et qui doit faire les vérifications.

Vérification avant de terminer

Corrigés — à ouvrir après avoir cherché

Étape 1

Champs : type="email", id et name identifiant ; type="password", id et name mot-de-passe. Le passage de password à text affiche le mot de passe en clair : type="password" protège l’écran du regard d’un voisin, pas le secret lui-même.

Étape 2

En GET, l’URL se termine par ?identifiant=…&mot-de-passe=Exercice-2026-soft. En POST, l’URL ne contient plus les données : elles voyagent dans le corps de la requête. Un mot de passe en GET reste dans l’historique du navigateur, les favoris, les journaux du serveur, ou sur un écran partagé.

Étape 3

const champ = document.querySelector("#mot-de-passe");
const bouton = document.querySelector("#bouton-oeil");

bouton.addEventListener("click", () => {
  if (champ.type === "password") {
    champ.type = "text";
    bouton.textContent = "Masquer";
  } else {
    champ.type = "password";
    bouton.textContent = "Afficher";
  }
});

Piège fréquent : un <button> placé dans un formulaire envoie le formulaire par défaut. Le bouton fourni porte type="button" pour l’éviter.

Étape 4

La console affiche le mot de passe en clair : tout script de la page peut le lire, et donc un script tiers peut l’envoyer ailleurs. Les contrôles du navigateur (minlength, required) se retirent en deux clics : seul le serveur peut vérifier de façon fiable.
