Partie 1 — Deux états et le poids des positions

Le problème

Une manufacture textile veut qu’un métier à tisser reproduise automatiquement un motif complexe, toujours identique, sur des centaines de mètres de tissu. Comment donner cette instruction à une machine ?

Au début du XIXe siècle, Joseph Marie Jacquard répond à ce problème avec une carte perforée : à chaque position de la carte, il y a un trou ou pas de trou. Cette information commande le passage des fils, motif après motif.

Info

Une carte perforée ne code pas directement notre écriture binaire actuelle — mais le principe est le même : deux états suffisent à commander une mécanique aussi complexe soit-elle.

Le bit

trou / pas de trou → deux états → 0 / 1

Un de ces deux états s’appelle un bit (contraction de l’anglais binary digit). C’est la plus petite unité d’information qu’une machine puisse représenter.

Activité

Avec une seule feuille de papier (vous pouvez écrire, découper, plier — rien d’autre), fabriquez en binôme une machine capable de représenter les entiers de 0 à 255, sans jamais rien écrire ni effacer pour changer de nombre représenté.

Vous devrez ensuite expliquer : comment un nombre est mémorisé par votre machine, et combien d’éléments de votre machine ont deux états possibles.

Le poids d’une position

Une écriture en base 10 fonctionne par position : dans 61027, le chiffre 6 ne vaut pas 6, il vaut 60000, parce qu’il est en position des dizaines de milliers.

Position 10⁴ 10³ 10² 10¹ 10⁰
Chiffre 6 1 0 2 7
Valeur 60000 1000 0 20 7

C’est exactement le même principe en base 2 : chaque position a un poids, qui est une puissance de 2 au lieu d’une puissance de 10.

Position (poids) 2⁷ 2⁶ 2⁵ 2⁴ 2³ 2² 2¹ 2⁰
Valeur du poids 128 64 32 16 8 4 2 1
Bit (exemple) 0 1 0 0 1 1 0 1

La valeur en base 10 est la somme des poids des positions à 1 :

64 + 8 + 4 + 1 = 77

L’écriture binaire 01001101 représente donc le nombre 77.

À retenir. 1. Deux états (bit) suffisent à coder n’importe quelle information. 2. Chaque position d’une écriture binaire a un poids, qui est une puissance de 2. 3. La valeur en base 10 est la somme des poids des positions valant 1.

Attention

Le nombre de bits disponibles limite le plus grand nombre représentable. Avec n bits, on peut représenter les entiers de 0 à 2ⁿ − 1 (par exemple, 0 à 255 avec 8 bits — un octet).

Partie 3 — Taille d’une
écriture binaire


Dans la machine des nombres, huit bits s’arrêtaient à 255. Python,
lui, écrit 2 ** 100 sans broncher. Mais la plupart des
langages et des processeurs travaillent avec une taille fixée à
l’avance : 8, 16, 32 ou 64 bits. Il faut donc savoir prévoir
combien de bits un nombre demande, et ce qui arrive quand il n’y en a
pas assez.

2¹⁰ = 1024, à peu près 1000. D’où un calcul mental rapide : 2²⁰ ≈ un

Combien de bits pour
écrire un entier ?


Le nombre de bits nécessaire pour écrire un entier N ≥ 1 est
le plus petit n tel que N ≤ 2ⁿ − 1, autrement dit tel
que N < 2ⁿ. C’est aussi la longueur de son écriture
binaire, sans zéros à gauche.


Exemple : 200. On a 2⁷ = 128 ≤ 200 < 256 = 2⁸, donc 200 demande
8 bits (11001000). Et 256 demande 9 bits :
100000000.




À retenir. N demande n bits quand
2ⁿ⁻¹ ≤ N < 2ⁿ : on encadre N entre deux puissances
de 2 consécutives.




En Python, deux façons d’obtenir ce nombre de bits :


>>> len(bin(200)) - 2      # on retire le préfixe 0b
8
>>> (200).bit_length()
8

Quand les bits manquent
: le dépassement


Sur une taille fixe, un résultat trop grand ne tient
pas : le bit en trop est perdu. Sur 8 bits, 255 + 1 donne
1 00000000 ; seuls les huit bits de droite restent, et le
résultat vaut 0. C’est un dépassement de
capacité (overflow). On compte alors « modulo 256 »,
comme un compteur kilométrique qui repasse à zéro.
