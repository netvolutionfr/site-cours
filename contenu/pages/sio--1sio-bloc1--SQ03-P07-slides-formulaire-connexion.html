Le mot de passe dans la page

Formulaire de connexion, champ masqué et envoi

Objectifs

  • Écrire un formulaire de connexion en HTML.
  • Montrer qu’un champ password ne cache le secret qu’à l’écran.
  • Comparer l’envoi en GET et en POST.

Prérequis : balises HTML, inspecteur, querySelector et addEventListener (cours sur le DOM).

Soft-Tech ouvre un espace client

Les clients veulent suivre leurs réparations et télécharger leurs factures sans appeler.

Il faut Côté navigateur, aujourd’hui Côté serveur, plus tard
Savoir qui se connecte Champ adresse e-mail Retrouver le compte
Vérifier que c’est bien lui Champ mot de passe Comparer le secret
Montrer ses factures, pas celles des autres — Contrôler les droits

Ce matin : identification, authentification, autorisation. Cet après-midi : la page.

Le formulaire

<form method="get">
  <label for="identifiant">Adresse e-mail</label>
  <input type="email" id="identifiant" name="identifiant">

  <label for="mot-de-passe">Mot de passe</label>
  <input type="password" id="mot-de-passe"
         name="mot-de-passe">

  <button type="submit">Se connecter</button>
</form>

name donne le nom de la donnée envoyée ; for relie l’étiquette à son champ.

text ou password : qu’est-ce qui change ?

type="text" type="password"
Affichage à l’écran Mistral2019! ●●●●●●●●●●●●
Valeur dans la page Mistral2019! Mistral2019!
Lisible par un script Oui Oui
Envoyé au serveur En clair En clair

Une seule ligne change : l’affichage. Le masquage protège du regard par-dessus l’épaule.

Démonstration : l’inspecteur

  1. Saisir un mot de passe fictif dans le champ.
  2. Clic droit sur le champ, Inspecter.
  3. Remplacer type="password" par type="text" dans le code affiché.
Prévoyez avant de voir Ce qu’on observe
Le mot de passe apparaît-il ? En clair, instantanément
Faut-il être administrateur ? Non : c’est votre navigateur

L’œil : la même chose en JavaScript

const champ = document.querySelector("#mot-de-passe");
const bouton = document.querySelector("#bouton-oeil");

bouton.addEventListener("click", () => {
  if (champ.type === "password") {
    champ.type = "text";
  } else {
    champ.type = "password";
  }
});

Le bouton « œil » des sites ne fait rien d’autre : il change le type du champ.

Le trajet d’un mot de passe

GET ou POST ?

method="get" method="post"
Où vont les données Dans l’URL : ?mot-de-passe=… Dans le corps de la requête
Visibles dans Barre d’adresse, historique, journaux du serveur Outils de développement seulement
À utiliser pour Une recherche, un filtre Un mot de passe, toute donnée sensible

POST ne chiffre rien : c’est HTTPS qui protège le trajet.

Ce que le navigateur ne protège pas

  • Le masquage : un clic dans l’inspecteur l’annule.
  • required, minlength : se retirent aussi dans l’inspecteur. Le serveur doit revérifier.
  • Les scripts de la page : tout script chargé peut lire le champ, même celui d’un site tiers.
  • Le trajet : sans HTTPS, le mot de passe circule en clair sur le réseau.

Ce qui protège vraiment se passe sur le serveur. Prochaine étape : comment il garde les mots de passe.
