Objectifs

  • Se repérer dans les fichiers d’un site existant avec VSCode.
  • Modifier du contenu HTML en respectant sa structure, et vérifier le résultat dans le navigateur.

Prérequis

  • Partie 1 de cette séquence : structure HTML, balises courantes, indentation (rappelées en express ci-dessous).
  • Notion de fichier et de dossier (Bloc 1, SQ01).

Sommaire

Étape Contenu
Étape 1 Explorer avant de modifier (10 min)
Étape 2 Modifier le contenu (30 min)

Info

Compétence B1.3 — Développer la présence en ligne de l’organisation, sous-compétence « Participer à l’évolution d’un site Web exploitant les données de l’organisation ». Cette activité en est une première application concrète : lire un site existant, puis le faire évoluer.

Consignes générales

En binôme, en autonomie, durée totale : 40 minutes environ (10 min étape 1, 30 min étape 2). Aucune aide extérieure (IA, recherche Internet) n’est autorisée : lire et modifier vous-mêmes le code existant est précisément l’objectif.

Rappel express

  • Une balise a une ouvrante et une fermante (<p>...</p>), sauf les éléments vides, qui n’ont pas de fermante (<img ...>).
  • L’indentation montre ce qui est imbriqué dans quoi — la respecter, pas seulement la recopier.
  • Réflexe permanent : modifier → enregistrer (Ctrl/Cmd + S) → rafraîchir le navigateur pour voir le résultat.

Le projet : Soft-Tech

site-reparation/
├── index.html              (page d'accueil)
├── assets/
│   ├── style.css           (CSS commun à tout le site)
│   └── images/
├── services/index.html
│   ├── reparation/index.html
│   └── entretien/index.html
├── atelier/index.html
└── conseils/index.html

Chaque rubrique a son propre dossier et son propre index.html ; une seule feuille de style (assets/style.css) est partagée par toutes les pages. VSCode s’utilise ici en deux zones : l’explorateur de fichiers (à gauche) pour l’arborescence, et l’éditeur (au centre) pour le contenu du fichier sélectionné. Pour voir le résultat, ouvrez le fichier .html directement dans le navigateur.

Étape 1 — Explorer avant de modifier

10 minutes.

  1. Ouvrez le dossier site-reparation dans VSCode, puis index.html.
  2. Ouvrez ce même fichier dans le navigateur : comparez le code et ce qui s’affiche.
  3. Retrouvez, dans le code, deux balises vues en partie 1 (h1, p, a, img, nav…) et notez à quoi elles correspondent visuellement.
  4. Ouvrez atelier/index.html : notez une différence et un point commun avec la page d’accueil (regardez notamment le <link> vers le CSS).

À produire : ces quatre observations, notées sur papier ou dans un fichier texte.

Critère de réussite de l’étape 1 : vous savez dire, sans rouvrir le code, où se trouve le fichier d’une page donnée, et citer deux balises du code en indiquant ce qu’elles produisent à l’écran.

Étape 2 — Modifier le contenu

30 minutes.

Avant de modifier : repérez la balise ouvrante et sa fermante correspondante, respectez l’indentation existante. Une balise mal fermée ne provoque pas toujours une erreur visible — en cas de doute, comparez avec une balise similaire déjà présente ailleurs dans le fichier.

  1. Dans atelier/index.html, ajoutez une nouvelle <section> (après les sections existantes, avant </main>) avec un titre <h2>Horaires d'ouverture</h2> et un paragraphe donnant des horaires de votre choix.
  2. Dans index.html (accueil), modifiez le texte du paragraphe introduction pour qu’il mentionne un nouveau service au choix (ex. : diagnostic gratuit, devis sous 24h).
  3. Après chaque modification : enregistrez, rafraîchissez le navigateur, vérifiez que la page s’affiche normalement (pas de texte disparu, pas de mise en page cassée).

À produire : les deux modifications, visibles et fonctionnelles dans le navigateur.

Vérification avant de terminer

Si l’un de ces points manque, reprenez votre travail avant de le montrer.
