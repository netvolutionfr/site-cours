Route, contrôleur et vue Blade

Du clic sur une URL au tableau des produits

Objectifs

  • Relier une URL à un contrôleur, un modèle et une vue
  • Afficher une collection avec Blade, sans faille d’affichage
  • Raconter le trajet d’une requête et localiser une erreur

Prérequis : le modèle Produit, sa table et au moins un produit en base.

Le problème

Les produits sont en base. Tinker les affiche, mais un client n’ouvre pas Tinker.

Que faut-il écrire pour que /produits affiche un tableau dans le navigateur ?

MVC : trois responsabilités

Composant Rôle Ici
Modèle Accès aux données Produit
Vue Présentation produits/index.blade.php
Contrôleur Coordination de la demande ProduitController

La route choisit le contrôleur ; la migration a préparé la table, une fois pour toutes.

Le contrôleur

php artisan make:controller ProduitController
public function index()
{
    $produits = Produit::all();

    return view('produits.index', ['produits' => $produits]);
}

La clé 'produits' devient la variable $produits dans la vue.

La route

// routes/web.php
use App\Http\Controllers\ProduitController;
use Illuminate\Support\Facades\Route;

Route::get('/produits', [ProduitController::class, 'index']);
  • GET /produits appelle ProduitController::index()
  • Rien n’est automatique : l’URL, la méthode et la vue sont reliées par ce code

La vue

{{-- resources/views/produits/index.blade.php --}}
<table>
    <tr><th>Libellé</th><th>Stock</th><th>Prix</th></tr>
    @foreach ($produits as $produit)
        <tr>
            <td>{{ $produit->libelle }}</td>
            <td>{{ $produit->stock }}</td>
            <td>{{ $produit->prix }} €</td>
        </tr>
    @endforeach
</table>

produits.index : le point sépare le dossier du nom, sans .blade.php.

Ce que fait Blade

  • @foreach parcourt la collection : $produits l’ensemble, $produit la ligne courante
  • {{ ... }} affiche une valeur en échappant le HTML : un <script> saisi reste du texte
  • Blade s’exécute sur le serveur : le navigateur reçoit du HTML, jamais la requête Eloquent

Toujours {{ }} pour une donnée ; {!! !!} n’échappe rien.

Le trajet d’une requête

Vérifier et ouvrir la page

php artisan route:list --path=produits
php artisan serve

Ouvrir http://127.0.0.1:8000/produits : « Clavier », 12, 49.9 €.

Le prix s’affiche 49.9 : le formatage monétaire est une question de vue, pas de stockage.

Localiser une erreur

Symptôme Premier contrôle
Could not open input file: artisan Êtes-vous à la racine du projet ?
Table produits absente La base configurée, puis migrate:status
Erreur d’affectation groupée $fillable et les noms des champs
Route introuvable (404) L’URL et route:list --path=produits
Vue introuvable, variable non définie Le chemin du Blade, la clé 'produits'
Tableau vide Produit::all() dans Tinker : le Blade ne crée pas de données

Restitution

Chacun, sur son poste projeté :

  1. Raconte le trajet de GET /produits, étape par étape
  2. Montre la ligne qui a fait disparaître la souris

À quel endroit la lecture des produits est-elle déclenchée : dans le contrôleur ou dans la boucle Blade ?

À retenir

  • Route → contrôleur → modèle → vue → HTML
  • Le contrôleur coordonne, il ne met en forme rien
  • {{ }} échappe : la vue affiche des données, elle n’exécute pas ce qu’elles contiennent
  • Filtrer, c’est changer la lecture, pas supprimer des lignes
